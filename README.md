# HealthWatch ระบบเฝ้าระวังสุขภาพพนักงานตามปัจจัยเสี่ยง

เว็บสำหรับ จป. และแพทย์อาชีวเวชศาสตร์ ใช้ติดตามผลตรวจสุขภาพตามปัจจัยเสี่ยงของพนักงาน 2 ด้าน คือ การได้ยิน (สัมผัสเสียงดัง) และสมรรถภาพปอด (สัมผัสฝุ่นหรือสารเคมี)
ระบบเทียบผลตรวจแต่ละปีกับผลปีแรกของคนนั้น เพื่อจับคนที่สุขภาพเริ่มแย่ลงจากงานก่อนจะป่วยจริง แล้วชี้แผนกที่มีปัญหาซ้ำกันหลายคนพร้อมมาตรการแก้ไข

งานนวัตกรรมวิชา อช 332 เทคโนโลยีสารสนเทศสำหรับงานอาชีวอนามัยและความปลอดภัย
ข้อมูลทั้งหมดในโปรเจกต์เป็นข้อมูลสมมติ ไม่มีข้อมูลสุขภาพของคนจริง

## เปิดดูทันที (โหมดสาธิต)
1. เปิดโฟลเดอร์ `healthwatch` ใน VS Code
2. คลิกขวาที่ `index.html` แล้วเลือก **Open with Live Server**
3. ระบบจะพาไปหน้าเข้าสู่ระบบ เลือกบทบาทแล้วกรอก PIN (PIN แสดงไว้ใต้ช่องกรอกในโหมดสาธิต)
4. เว็บใช้ข้อมูลสมมติ 60 คน 5 แผนก ปี 2566–2569 ทันที ยังไม่ต้องเชื่อม Google Sheet
   ลองเปิดประวัติของพนักงานแผนกปั๊มโลหะ เช่น E-0002 เพื่อดูออดิโอแกรมที่มีรอยบุ๋มจากเสียงดัง

ต้องต่ออินเทอร์เน็ตเพื่อโหลดกราฟ (Chart.js) และฟอนต์ ถ้าออฟไลน์ ตัวเลขและตารางยังใช้งานได้ ส่วนกราฟจะแสดงเป็นตารางแทน

ข้อมูลที่กรอกเพิ่มในโหมดสาธิตเก็บไว้ในเบราว์เซอร์เครื่องนี้เท่านั้น กดปุ่ม "ล้างข้อมูลที่กรอกเพิ่ม" บนแถบสีเหลืองเพื่อเริ่มใหม่

## ฟีเจอร์

### 1. เข้าสู่ระบบสองระดับ
| บทบาท | PIN สาธิต | เห็นอะไร |
|---|---|---|
| จป. / แพทย์ | `1234` | ทุกหน้า รวมถึงรหัสพนักงานรายคน ประวัติรายคน และบันทึกผลตรวจ |
| หัวหน้าแผนก | `5678` | เลือกแผนกตัวเอง เห็นเฉพาะตัวเลขสรุป กราฟ และมาตรการของแผนกนั้น ไม่เห็นรหัสพนักงาน เข้าหน้าประวัติรายคนและหน้าบันทึกไม่ได้ |

- บทบาทปัจจุบันแสดงที่มุมขวาบน พร้อมปุ่มออกจากระบบ ปิดแท็บแล้วต้องเข้าสู่ระบบใหม่
- กรอก PIN ผิด 5 ครั้ง ต้องรอ 30 วินาที
- เปลี่ยน PIN ได้ที่ `window.HW_PINS` ใน `config.js`
- **ข้อจำกัด:** PIN ในหน้าเว็บใช้สาธิตการแบ่งสิทธิ์เท่านั้น ใครเปิดไฟล์ก็อ่านได้ และข้อมูลทั้งหมดยังถูกโหลดมาที่เบราว์เซอร์ ระบบจริงต้องตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ (Apps Script) และส่งเฉพาะข้อมูลที่บทบาทนั้นมีสิทธิ์เห็น

### 2. หน้าภาพรวม (`index.html`)
- ตัวเลขสรุป: คนที่ตรวจแล้ว ผลผิดปกติ ต้องเฝ้าระวัง และยังไม่ได้ตรวจในปีล่าสุด
- เลือกปีและประเภทการตรวจได้
- กราฟผลตรวจแยกตามแผนก และกราฟแนวโน้มจำนวนคนผลผิดปกติรายปี
- กล่อง "แผนกที่ควรตรวจสภาพแวดล้อมการทำงาน" พร้อมมาตรการแก้ไข (ดูข้อ 5)
- ตารางรายชื่อที่ต้องติดตาม พร้อมเหตุผล กดรหัสพนักงานเพื่อดูประวัติ (เฉพาะ จป. / แพทย์)

### 3. หน้าบันทึกผลตรวจ (`record.html`)
- กรอกผลการได้ยินตามใบออดิโอแกรม 7 ความถี่ต่อหู (500, 1,000, 2,000, 3,000, 4,000, 6,000, 8,000 Hz) หรือสมรรถภาพปอด (FVC %, FEV1 %, FEV1/FVC %)
- กด Tab ไล่หูขวาจากบนลงล่างก่อน แล้วจึงหูซ้าย
- ระบบประเมินผลทันทีหลังบันทึก บอกเหตุผล สิ่งที่ต้องทำต่อตามกฎหมาย และข้อมูลเสริม (OSHA, รอยบุ๋ม)
- ตรวจข้อมูลก่อนบันทึก และบอกวิธีแก้ เช่น
  - รหัสพนักงานต้องเป็นตัวอักษรอังกฤษ ตัวเลข และขีด (กันการใส่ชื่อจริง)
  - ปีต้องเป็น พ.ศ. ถ้ากรอกเป็น ค.ศ. ระบบจะบอกให้บวก 543
  - ค่าผลตรวจต้องอยู่ในช่วงที่เป็นไปได้ และ FEV1/FVC ต้องไม่เกิน 100%
  - กันการบันทึกผลซ้ำ (คนเดียวกัน ปีเดียวกัน ประเภทเดียวกัน)
- เมื่อเชื่อม Apps Script แล้ว ผลผิดปกติจะส่งแจ้งเตือน LINE ถึง จป. พร้อมมาตรการแก้ไขฉบับย่อ

### 4. หน้าประวัติรายคน (`person.html`)
- สรุปผลการได้ยินปีล่าสุด พร้อมสิ่งที่ต้องทำ (ตรวจซ้ำภายใน 30 วัน, แจ้งลูกจ้างภายใน 7 วัน)
- **ออดิโอแกรม** หูขวา (O สีแดง) และหูซ้าย (X สีน้ำเงิน) แบบที่ใช้จริง: แกนนอนเป็นความถี่ แกนตั้งเป็น dB HL กลับหัว เทียบเส้นปีแรกกับปีที่เลือก เห็นรอยบุ๋มที่ 3,000–6,000 Hz ชัด
- กราฟระดับที่แย่ลงมากที่สุดเทียบปีแรกในแต่ละปี พร้อมเส้นเกณฑ์ 10 และ 15 dB
- ตารางออดิโอแกรมรายปี ตัวเลขที่แย่ลงถึงเกณฑ์เป็นสีแดง เฝ้าระวังเป็นสีส้ม
- กราฟ FVC และ FEV1 พร้อมเส้นเกณฑ์ 80%
- ตารางผลรายปีพร้อมผลประเมิน

### 5. มาตรการแก้ไขตามลำดับชั้นการควบคุมอันตราย
เมื่อแผนกเข้าเกณฑ์ ระบบแสดงมาตรการเรียงจากได้ผลมากไปน้อย: การกำจัด → การทดแทน → การควบคุมทางวิศวกรรม → การควบคุมทางการบริหาร → อุปกรณ์ป้องกันส่วนบุคคล
แยกเนื้อหาตามปัจจัยเสี่ยง (เสียงดัง / ฝุ่นหรือสารเคมี) พร้อมรายชื่อกฎหมายและมาตรฐานที่เกี่ยวข้อง
เนื้อหาทั้งหมดอยู่ใน `data/controls.js` แก้ได้โดยไม่ต้องแตะตรรกะ **ชื่อกฎหมายและเนื้อหาต้องตรวจสอบกับเอกสารอ้างอิงฉบับจริงก่อนใช้**

### 6. ใช้งานบนมือถือและการเข้าถึง
- ใช้ได้บนจอกว้าง 375 px ขึ้นไป ตารางเปลี่ยนเป็นการ์ดทีละแถวบนมือถือ
- ใช้คีย์บอร์ดได้ทุกปุ่มและช่องกรอก (Tab, Enter, Space, ลูกศรสำหรับตัวเลือก) มีกรอบโฟกัสชัดเจน
- สีตัวหนังสือผ่านเกณฑ์ความต่างสี WCAG AA (4.5:1) ทั้งโหมดสว่างและโหมดมืด
- รองรับโหมดมืดตามการตั้งค่าเครื่อง

### 7. ข้อความแจ้งเตือนเมื่อเกิดปัญหา
ทุกปัญหาแสดงเป็นภาษาไทยพร้อมวิธีแก้ทีละข้อและปุ่มลองใหม่ เช่น
- ลิงก์ใน `config.js` ผิดรูปแบบ (ไม่ได้ลงท้ายด้วย `/exec`)
- ไม่มีอินเทอร์เน็ต เชื่อมต่อ Apps Script ไม่ได้ หรือตอบช้าเกิน 20 วินาที
- Apps Script ไม่ได้ตั้ง Who has access: Anyone หรือยังไม่ได้ Deploy เวอร์ชันใหม่
- ไม่มีข้อมูลผลตรวจ หรือโหลดกราฟไม่ได้
- ถ้าโหลดข้อมูลเดิมไม่ได้ หน้าบันทึกจะปิดปุ่มบันทึกไว้ก่อน เพื่อกันข้อมูลซ้ำ

## เชื่อม Google Sheet และ LINE
1. สร้าง Google Sheet ใหม่ เปลี่ยนชื่อแท็บเป็น `records`
2. **ไฟล์ → นำเข้า → อัปโหลด** เลือก `data/mock-data.csv` แล้วเลือก "แทนที่ชีตปัจจุบัน"
   (ถ้าเคยนำเข้าไฟล์รุ่นเก่าที่มีแค่ 3 ความถี่ ต้องนำเข้าใหม่ Apps Script จะแจ้งถ้าหัวตารางไม่ตรง)
3. **ส่วนขยาย → Apps Script** ลบโค้ดเดิม แล้ววางโค้ดจาก `apps-script/Code.gs`
4. แก้ค่า token และผู้รับใน `setupLineConfig()` แล้วเลือกฟังก์ชันนี้กด **Run** 1 ครั้ง ผู้รับใส่ได้ 3 แบบ: `ALL` = ทุกคนที่แอดบอทเป็นเพื่อน, `Uxxx` = User ID คนเดียว, `Uxxx,Uyyy` = หลายคน (หรือรัน `useLineBroadcast` เพื่อเปลี่ยนเป็น `ALL` โดยไม่แตะ token)
5. เลือกฟังก์ชัน `testLine` กด **Run** ถ้า LINE เด้งแปลว่าตั้งค่าถูก ถ้าขึ้น `false` ให้รัน `checkLine` จะบอกสาเหตุเป็นภาษาไทย (ไม่พบค่า, ID ผิดรูปแบบ, รหัสตอบกลับจาก LINE เช่น 401 = token ผิด)
6. **Deploy → New deployment → Web app** ตั้ง Execute as: Me และ Who has access: Anyone
7. ก๊อปลิงก์ที่ลงท้ายด้วย `/exec` ไปวางใน `window.HW_API_URL` ของ **`config.local.js`** (สร้างไฟล์นี้เองถ้ายังไม่มี ไฟล์นี้อยู่ใน `.gitignore` จึงไม่ขึ้น GitHub) ห้ามใส่ใน `config.js` เพราะไฟล์นั้นขึ้น GitHub
8. ทุกครั้งที่แก้ Code.gs ต้องไปที่ **Manage deployments → แก้ไข → New version**

ตรวจว่าเชื่อมสำเร็จ: เปิดลิงก์ `/exec?action=list` ในแท็บใหม่ ต้องเห็นข้อความที่ขึ้นต้นด้วย `{"ok":true`
อยากกลับไปใช้โหมดสาธิต: แก้ `config.js` เป็น `window.HW_API_URL = ""`

**ข้อควรระวัง:** Web App ที่ตั้ง Who has access: Anyone ใครมีลิงก์ก็อ่านข้อมูลได้ ใช้กับข้อมูลสมมติเท่านั้น ถ้าจะใช้กับข้อมูลจริงต้องเพิ่มการตรวจสิทธิ์ใน Apps Script ก่อน

## เกณฑ์ที่ระบบใช้
| การตรวจ | เฝ้าระวัง | ผิดปกติ |
|---|---|---|
| การได้ยิน | หูข้างใดแย่ลง 10–14 dB ที่ความถี่ใดความถี่หนึ่ง (500–6,000 Hz) จากผลครั้งแรก | หูข้างใดแย่ลงตั้งแต่ 15 dB ที่ความถี่ใดความถี่หนึ่ง (500–6,000 Hz) จากผลครั้งแรก → ตรวจซ้ำภายใน 30 วัน และแจ้งลูกจ้างภายใน 7 วัน |
| สมรรถภาพปอด | FEV1 ลดลง 8–14.9% จากปีแรก | FEV1 ลดลงตั้งแต่ 15%, FEV1/FVC ต่ำกว่า 70% หรือ FVC ต่ำกว่า 80% |

- ค่าตั้งต้นคือผลตรวจครั้งแรกของคนนั้นในประเภทเดียวกัน
- เกณฑ์การได้ยิน "ผิดปกติ" ตามประกาศกรมสวัสดิการและคุ้มครองแรงงาน เรื่อง หลักเกณฑ์และวิธีการจัดทำโครงการอนุรักษ์การได้ยินในสถานประกอบกิจการ พ.ศ. 2561
- เกณฑ์ "เฝ้าระวัง" 10 dB โปรเจกต์กำหนดเองเพื่อเตือนก่อนถึงเกณฑ์ตามประกาศ
- 8,000 Hz บันทึกและแสดงในกราฟ แต่ไม่ใช้ตัดสินผล
- ข้อมูลเสริม ไม่ใช้ตัดสินผล: OSHA Standard Threshold Shift (ค่าเฉลี่ย 2,000/3,000/4,000 Hz แย่ลงตั้งแต่ 10 dB) และการพบรอยบุ๋มที่ 3,000–6,000 Hz (Coles และคณะ 2000)
- ตัวเลขเกณฑ์ทั้งหมดอยู่ใน `CRITERIA` ใน `app.js` ที่เดียว พร้อมแหล่งอ้างอิง **ตรวจสอบกับเอกสารฉบับจริงก่อนใช้**
- แผนกจะถูกแจ้งให้ตรวจสภาพแวดล้อมเมื่อมีคนผลผิดปกติตั้งแต่ 3 คนและคิดเป็น 20% ขึ้นไปของคนที่ตรวจ

## ไฟล์ในโปรเจกต์
| ไฟล์ | หน้าที่ |
|---|---|
| `login.html` | หน้าเข้าสู่ระบบ |
| `index.html` | หน้าภาพรวม |
| `record.html` | หน้าบันทึกผลตรวจ |
| `person.html` | หน้าประวัติรายคน |
| `app.js` | ตรรกะคำนวณ ตรวจข้อมูล เชื่อม Apps Script จัดการสิทธิ์ และข้อความแจ้งเตือน |
| `style.css` | หน้าตาเว็บทั้งหมด รวมโหมดมืดและมือถือ |
| `config.js` | ลิงก์ Apps Script และ PIN |
| `data/mock-data.js`, `data/mock-data.csv` | ข้อมูลสมมติชุดเดียวกัน (ห้ามใช้ข้อมูลสุขภาพของคนจริง) |
| `data/controls.js` | เนื้อหามาตรการแก้ไขและกฎหมายอ้างอิง |
| `tools/gen-mock-hearing.js` | สคริปต์สร้างข้อมูลการได้ยินสมมติใหม่ (ไม่จำเป็นต่อการใช้งานเว็บ ต้องมี Node.js) |
| `apps-script/Code.gs` | โค้ดฝั่ง Google Sheet: อ่าน/บันทึกข้อมูล ตรวจข้อมูล ประเมินผล ส่ง LINE |
| `CLAUDE.md` | กติกาการพัฒนาโปรเจกต์ |
| `DEVLOG.md` | บันทึกการพัฒนาแต่ละฟีเจอร์ ปัญหาที่เจอ และวิธีแก้ |

ใช้ HTML, CSS และ JavaScript ล้วน ไม่มีขั้นตอน build

## เผยแพร่บน GitHub Pages และแชร์ให้คนอื่นกรอก
- เว็บบน GitHub Pages เปิดเป็น**โหมดสาธิต**เสมอ เพราะ `config.js` ในโค้ดว่าง (ลิงก์จริงอยู่ใน `config.local.js` ที่ไม่ขึ้น GitHub)
- **แชร์ให้คนอื่นบันทึกลง Google Sheet จริง:** ส่งลิงก์แบบนี้ให้เฉพาะคนที่ไว้ใจ
